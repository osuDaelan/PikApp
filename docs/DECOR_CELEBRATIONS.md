## Three-second new-item sparkles

Every mounted tile that changes from uncollected to collected gets a brief mint/cyan radial glow and six small white/cream four-point twinkles. Positions are chosen around the central oval dead zone when the effect mounts. Twinkles gently grow, drift away from the artwork, and recede in staggered pulses; the whole layer fades out over three seconds and is then removed. The glow subsides earlier so the artwork stays readable. This layer runs alongside the short regular confetti or rare-star burst and is independent of their animation-end cleanup. Completing the last item can show both tile sparkles and the existing set blast.

`useDecorTileMotion.js` tracks this temporary presentation separately as `data-sparkling`; it does not change collection IDs or storage. It skips saved selections on mount, cancels on uncollect/unmount, and clears when reduced motion becomes enabled. `DecorImageTile.jsx` conditionally mounts `NewDecorSparkles.jsx`; `new-decor-sparkles.css` owns its appearance. The three-second cleanup is in the hook; the matching `3s` outer CSS fade must be changed with it if retiming. Tune count/size/delay in `TWINKLES`, placement in the shared `sparkleLayout.js`, and glow/color/pulses in CSS. Removing the component import/render removes this visual layer without affecting the other celebrations.

Performance: six small SVGs and one CSS radial gradient only while a newly selected tile sparkles, no image requests, dependencies, canvas, RAF loop, or idle particle elements. CSS uses finite opacity/transform animations. The active layer has one cleanup timer and a temporary motion-preference listener; both are removed on cleanup. Bulk additions animate only mounted entries whose collection state changes, without replaying old collected tiles.

## Completing a set

A set is one existing costume/design row: for example, standard Chef Hat and rare Chef Hat are separate sets. Only the available colors or numbered designs in that row are required. `setCompletion.js` precomputes the sets and detects incomplete → complete transitions. `useSetCompletion.js` watches collection updates, so manual toggles and bulk selection use the same rule. Existing complete saves do not celebrate on initial load; revealing a rare row or removing an item also does not count. Uncollecting and later completing the set again does count. A bulk update that completes several sets produces one event containing all newly completed sets.

`SetCompletionCelebration.jsx` mounts one pointer-transparent viewport canvas and a short accessible confirmation message. It anchors the sprays to the first newly completed row visible in the viewport, with a viewport fallback. `setConfetti.js` draws two upward/inward sprays of small pink, yellow, green, blue, and cream pieces, with gravity, drag, tumbling, and nine small gold glints. The burst lasts about 2.2 seconds; the message/cleanup fallback lasts at most 2.4 seconds. A newer completion replaces the active effect rather than accumulating canvases. Resize, hidden-tab transitions, and unmount stop the drawing. Reduced-motion users get the message without particles.

Performance: no new library or image assets; 76 confetti particles on narrow viewports or 112 on desktop, plus nine sparkles. Canvas backing resolution is capped at 2× device scale. One RAF loop exists only during a burst; the canvas and message are removed afterward. Controls remain usable throughout. Source: `setConfetti.js`, `SetCompletionCelebration.jsx`, `set-completion.css`, `setCompletion.js`, and `useSetCompletion.js` under `src/features/decor/`. The app shell mounts the overlay once; costume rows expose a stable `data-decor-set` anchor. Collection IDs/storage are unchanged.

## Selecting a rare tile

Only costumes whose names end with ` (Rare)` use the star variant (`isRareCostume` in `collection.js`), covering 74 existing entries. Gold-themed event costumes do not automatically qualify. `DecorGroup.jsx` passes a stable boolean to the memoized image tile. `RareTileStars.jsx` draws five white SVG stars with blue glow and three smaller gold four-point glints; CSS supplies staggered expansion, slight outward movement, rotation, and fade over 600ms plus up to 90ms delay. The tile keeps its small 7.5% pop with a 720ms duration so the stars can finish. Rare collection renders no confetti-ring pieces.

Regular tiles retain the approved 400ms pop / 380ms confetti ring. Uncollecting retains the 220ms settling dip. Stars/confetti are created only during collection and removed at animation end. `useDecorTileMotion.js` also clears interrupted effects after 900ms or when reduced motion becomes enabled, with no idle listener/timer per tile. Reduced motion skips both tile effects. Saved collected tiles load without particles.

Each rare burst generates a fresh random arrangement around the Pikmin, replacing the initial ±3px anchor jitter and the subsequent unrestricted layout over the artwork. `RareTileStars.jsx` chooses positions once when the burst mounts and holds them steady through rerenders. The shared oval exclusion described below now protects the character. Star count, sizes, colors, glow, delays, and duration are unchanged; drift now points away from the character and shortens near tile edges. This adds no animation loop or work to idle tiles.

To tune the rare effect, edit the shared geometry in `sparkleLayout.js` and movement magnitudes in `STAR_MOTION` in `RareTileStars.jsx`; sizes, glow, timing, and `rare-star-burst` live in `decor-tile-motion.css`. The earlier anchor-jitter version is preserved in Git commit `64c4b72`, and the unrestricted random layout in `2a5a575`. To tune the set blast, edit the palette, counts, velocity/gravity, duration, and sparkles in `setConfetti.js`; message styling is in `set-completion.css`. Set detection and storage do not need changes for visual revisions.

## Oval dead zone around the Pikmin

Temporary debug view: `DecorDeadZoneDebug.jsx` wraps the tracker only in Vite development mode. It initially shows a translucent red dashed oval on every image tile, with a Hide/Show toggle, separate Width −/+ and Height −/+ controls, and Reset size. Defaults are 32×76px; both dimensions change in 2px steps. Width is limited to 12–44px and height to 24–88px so legal particle positions still exist within the tile. The controls and overlay share one geometry value, supplied through `SparkleDeadZoneContext.js` to both particle components. New bursts use the adjusted size; active bursts retain their original layout to avoid jumping. Debug values reset on reload or leaving the tracker and do not change saved collection data or production defaults. It uses pointer-transparent CSS pseudo-elements. Production rendering returns the ordinary tracker with no debug controls or oval. Remove the wrapper/import from `DecorSection.jsx`, then delete `DecorDeadZoneDebug.jsx` and `decor-dead-zone-debug.css` when finished; the context can keep supplying default geometry to the normal effects.

The user's oval sketch clarifies that stars should surround the character rather than spawn on its body. Both rare stars and new-item twinkles now use `createSparkleLayout` in `sparkleLayout.js`. It excludes an oval centered at (36, 52) with radii (16, 38), inside a 72×104px particle area. This matches the 76×120px tile's inner border space and keeps the label below the effect clear. It is a shared approximate character oval, not per-PNG silhouette detection; adjust `SPARKLE_DEAD_ZONE` if unusually wide decor artwork needs more space. The mint aura remains intentionally behind/over the character; it is not a star spawn.

Placement checks each particle's full bounding box against the oval, including room for peak scale/rotation. It prefers 12px spacing without predefined slots or angles. Each particle gets at most 96 random candidates, choosing the best legal gap when crowded; safe corners provide a bounded fallback even for a constant random source. Drift points away from the oval on both axes and is clamped to the tile bounds, so stars do not wander into the protected center or off the tile. Small twinkles use the same rule instead of always rising toward the character. Timing, counts, colors, and the three-second fade remain unchanged. Soft halos can extend beyond a glyph's bounds; the rule protects star artwork rather than trying to remove all diffuse light.
